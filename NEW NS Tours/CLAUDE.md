# CLAUDE.md — NEW NS Tours

This file provides guidance to Claude Code when working in this repository.

## Project

Pitch-deck for a Georgia corporate team-building trip, sold by DMC "NS Tours" to corporate MICE clients. Two parallel HTML deck concepts live in `decks/` — self-contained single-file HTML (fonts + photos embedded as base64 data URIs, no external requests, no build step). Source copy for both is `slides_copy_ru.md` (10 scenes, Russian).

## Rules

- **Never reference or copy from `../NS tours-presentation`.** That's a separate, earlier Codex-built deck (concept "Georgia at Full Volume", 5 modular priced programs) that the client explicitly rejected. Do not pull its design, palette, or copy into this project. The only thing that folder is allowed to contribute is the raw source photography in `assets/user-gallery/` (the client's own photos) — reading/reusing those images is fine, its *design* is not.
- **Concept 1 (`decks/concept1-tbilisi-signboard.html`) is locked.** Client confirmed it — don't change palette (`#F7F1E8` milk / `#B8323C` garnet / `#F2A33A` saffron / `#1F8A70` emerald / `#2E2A27` graphite / `#E8D8BF` sand), fonts (Unbounded / Manrope / Cormorant Garamond), or the "photo only on slides 1/5/7/10, masked as signboard/arch/plaque/stamp" discipline unless explicitly asked. Full spec: `presentation_style_guide_ru.md`.
- **Concept 2 (`decks/concept2-engraving-bright.html`) is the active line of work** — client prefers it, and it is now restructured away from `slides_copy_ru.md`'s 10-scene single-journey copy. It's **8 slides**: cover, a menu slide listing all 5 programs with prices (`.menu-card`/`.menu-row`), one slide per program (`.price-tag` pill showing price/duration/group size), and a closing contact slide (`.contact-block`). Pricing model is settled: **menu of 5 independently-priced one-day programs** ($160/$140/$310/$175/$210 per person, from the original docx — client hasn't re-confirmed these are still current, ask if it's been a while), each for a group of 10+. Design tokens: bright diagonal duotone fields per slide (`--rust #D2481F`/`#E85A2C`, `--mustard #E2A317`/`#F0B928`, `--teal #0F9C82`/`#17B294`, `--grape #8B3F6B`/`#A9477F`, each as a `linear-gradient(112deg, light 0 57%, dark 57% 100%)`), ink-line "engraving" doodle per slide, rotated parchment `.card` (`#FBF3E0`) styled like a torn program page, Polaroid-style `.postcard` photo taped on every slide, handwritten `.note` in the margin (must NOT restate the `.humor` line — give it a distinct fact/detail instead). Fonts: Yeseva One (headlines) + Caveat (handwritten) + Manrope (body). Fonts are fetched once and cached as base64 in a scratchpad `fonts2/` folder during a session — if you need to re-touch the HTML, the template with `__PLACEHOLDER__` tokens plus the substitution script are NOT persisted in this repo (they lived in session scratchpad); re-fetch fonts from `fonts.googleapis.com/css2?family=...` with a Chrome-like `User-Agent` (needed for woff2 + correct cyrillic subset) if starting fresh.
- **Slide 8's `.contact-block` has real contact info** (Нини Салуквадзе, Генеральный директор, +995 551 91 50 90, info@nstours.ge, nstours.ge) — no longer a placeholder, don't revert it to bracketed placeholder text.
- **`logo.png`** (project root, gold spiral + "NS Tours" wordmark, transparent PNG) is embedded in Concept 2's header (`.brand-logo`, replacing the old plain-text wordmark). Concept 2 only — Concept 1 is locked, don't add it there without being asked.
- **Decorative ornament policy: don't add Georgian ornamental patterns/borders.** Two independent design reviews (general art direction + a Georgian-decorative-arts specialist) both concluded that repeating ornamental motifs (carpet/rug patterns, ropework borders, fake Mkhedruli lettering) would read as generic "ethnic stock" decoration and fight the flat duotone-field system — the client's Georgian identity already comes through credibly via real photos/toponyms (Tbilisi, Kakheti, Orbeliani market, Chateau Agarani) and the content itself. The one exception made: a single line-art St. Nino grapevine cross (`.doodle` on slide 1 only, drooping-arm cross silhouette with small circle "grapes" at the arm-ends/tips) as a one-time signature mark on the cover — do not repeat it on other slides, and do not add any other ornamental element without a specific reason tied to a genuinely empty zone (as slide 2's 5-point star doodle was added to fill real empty space, not for decoration's sake).
- **The slide count and the CSS track width are coupled — this WILL break silently if you change one without the other.** `.track{width:N00%}` must equal `(number of <section class="slide">) × 100%`, and `.slide{width:...%; flex:0 0 ...%}` must equal `100/n%`. The nav JS computes `translateX(-(i*(100/n))%)` from `slides.length` automatically, but the CSS values are hardcoded and won't follow it — if you add/remove a slide, update both `.track` and `.slide` width by hand. Symptom when it's wrong: slides after the first render showing content shifted/cut off or fully blank (the fix that was needed going from 10→8 slides here).
- **QA any HTML slide edit visually before calling it done.** A local Playwright/Chromium install exists at `%LOCALAPPDATA%\ms-playwright` (or reinstall via `npx playwright install chromium` into a throwaway npm project). Both decks support `?slide=N` in the URL to jump straight to a slide for screenshotting — use `npx playwright screenshot --viewport-size=1600,1000 --wait-for-timeout=1000 "file:///<path>?slide=N" out.png`. Screenshot *every* slide after a structural change, not just the ones you edited — the track-width bug above only shows up on slides you didn't directly touch. Card/photo/note layering has also previously broken when body-text length grew past 3 lines and pushed the centered card up into the top-margin handwritten note.
- Both decks are pure vanilla HTML/CSS/JS — no dependencies, no build. Edit in place, no compilation step.
